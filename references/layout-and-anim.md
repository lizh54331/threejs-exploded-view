# 拆解构图与动画

> 拆解页 80% 的"不好看"都出在这两件事上：构件互相遮挡、位移量没有参照。

---

## 1. 先选构图路线

| 路线 | 位移主轴 | 适合 | 代价 |
|---|---|---|---|
| **屏幕平面扇形**（默认） | x / y 为主，z ≤ 0.4 | 大多数产品与场景 | 需要挑相机角度，让扇形不打架 |
| **纵深堆叠** | z 为主（沿视线） | 层状结构：相机、手机、镜头 | 必须让外壳半透明，否则内部件看不见 |
| **分组合并** | 混合 | 构件 > 10 个 | 构件清单会被合并，颗粒度变粗 |

判断方法：把相机放到默认机位，问一句"每个构件朝哪个方向移动会在屏幕上散开"。屏幕平面的两个轴就是 x/y —— 优先用它们。

---

## 2. 遮挡检查（每次出图必做）

1. 拆解态截图；
2. 逐个看标签：**标签的锚点在屏幕上是否落在自己的构件上**；如果落在别的构件上，说明被挡了；
3. 被挡就三选一：换方向、加大位移、让挡它的构件半透明。

外壳半透明的写法（只影响拆解态）：

```js
const shellMats = [];       // 收集外壳材质
function ghost(k) {         // k = explode 0..1
  for (const m of shellMats) {
    m.transparent = k > 0.02;
    m.opacity = 1 - 0.86 * k;   // 0.14 左右刚好能看穿
    m.depthWrite = k < 0.18;    // 太透明时关掉写深度，避免自遮挡发黑
  }
}
```

## 3. 位移量怎么定

经验公式：`distance ≈ 构件包围盒最大边 × 0.6 ~ 1.2`

- 太小（< 0.4 倍）：看起来只是"错位"，不像拆开；
- 太大（> 1.5 倍）：跑出画面，标签也会被挤到屏幕外；
- 同一层的构件用同一档位移，形成"层"的节奏：如面板 2.4 / 龙骨 1.2 / 立柱 −2.2 / 栏杆 3.5。

层的顺序（从外到内）：
```
围护（栏杆/盖板）  位移最大，最上层
面层（面板/外壳）  次之
骨架（梁/支架）    小位移，几乎留在原地
基础（立柱/底座）  向下
陈设（配件/摆件）  向侧上
环境（地面/山体）  向后下方
```

## 4. 动画曲线与时长

```js
// 每帧指数逼近：稳定、无状态、帧率无关
const k = 1 - Math.pow(0.0016, dt);        // dt ≈ 16ms 时 k ≈ 0.10
explode += (target - explode) * k;
if (Math.abs(target - explode) < 0.0005) explode = target;
```

- 收敛时间约 0.6–0.8 s；要更快把底数改成 `0.0004`，更慢改 `0.004`；
- **不要**用线性插值（起手太生硬）或 spring（会来回抖，拆解图不该抖）；
- 位置更新必须用 `base + direction * distance * explode`，保证 `explode = 0` 时精确复位（不要累加）。

高亮呼吸（只作用于选中件）：

```js
const pulse = 0.3 + Math.sin(t * 3.4) * 0.12;
// 叠加在基础 emissiveIntensity 上
```

## 5. 相机

- 默认机位：主体包围盒对角线 × 1.3–1.6 的距离，视场 30°–36°（长焦更"产品图"）；
- 拆解态若超出画面：**不要**自动推镜头（会和用户操作打架），改为把默认机位放远一点，或缩小位移；
- 允许的自动动作只有一次性的"聚焦到构件"，且用户一拖拽就立即停止；
- `maxPolarAngle` 限制在地平线以上（`Math.PI * 0.5`），否则会翻到地面以下看到空腔。

---

## 6. 拆解态的三个加分项

1. **地面/底座光池**：加色混合的径向贴图平面，让构件"浮"在一个光圈里，而不是飘在虚空；
2. **浮尘**：200–300 个 `Points`，慢速上浮，`AdditiveBlending`，透明度 0.4–0.6；
3. **背光板**：主体后方一块大柔光面，把轮廓切出来（暗背景下尤其明显）。
